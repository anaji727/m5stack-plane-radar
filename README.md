# M5Stack Basic / Gray 用ローカル航空機レーダー

ESP32-Plane-Radar を M5Stack Basic / Gray（物理ボタン A/B/C、320×240 LCD）へ移植したファームウェアです。
自宅の dump1090-mutability から `aircraft.json` を HTTP で取得します。常用は USB 給電を想定しています。

接続先の初期値：`http://192.168.1.101/dump1090/data/aircraft.json`

## 2026-09-20 設定画面から戻る操作を追加

Cを短く押すと設定を開き、設定画面でCを約1秒長押しするとメイン画面に戻ります。保存済みの設定は保持します。ブラウザの未保存の入力は、戻る前に保存してください。
初回設定が未完了でも戻れますが、`SETUP NEEDED` と表示し、URLと座標を保存するまで機体取得は開始しません。

## 2026-09-20 画面回転修正

画面を右に90度回転しました。レーダーは上240×240、接続状態・操作案内は下240×80に配置し、設定画面も縦向きに収めています。
既に初版を導入済みの場合は、設定を保持できる `firmware/firmware.bin` のアプリ更新（書き込み先 `0x10000`）を使用してください。

## 最初に使う

1. 下記の方法で M5Stack に書き込みます。
2. スマホまたは PC を Wi-Fi **M5Radar-Setup** に接続します。
3. ブラウザで **http://192.168.4.1** を開きます。
4. **Configure WiFi** で自宅の 2.4 GHz Wi-Fi を設定します。
5. **Setup / Parameters** の設定欄で、上記 URL とレーダー中心の緯度・経度を保存します。WiFi 設定ページに同じ項目が表示される場合はそこで入力できます。
6. 自宅 Wi-Fi 接続後は **http://m5radar.local** でも設定できます。名前解決できなければ、本体の設定画面に表示される LAN IP を開いてください。
7. **Cを約1秒長押し**するとレーダーに戻ります。設定保存後はポータルの **Exit** でも戻れます。

緯度経度は初回に自分で入力します。緯度は -90～90、経度は -180～180 の十進数です。日本なら通常は両方とも正数です。
初期位置を勝手に指定しないため、URL と有効な座標を保存するまで機体取得を始めません。
URL と座標は再起動後も保存されます。Wi-Fi パスワードをソースコードに書く必要はありません。
設定用 AP と LAN 設定画面は認証なしのローカル設定機能です。インターネットへ公開する構成は想定していません。

## 操作と画面

| 操作 | 動作 |
|---|---|
| A ボタン | 距離範囲を順番に変更し保存 |
| B ボタン | 明るさを変更（再起動時は標準へ戻る） |
| C ボタン | 設定 AP を開く。保存済み Wi-Fi を消去しない |
| 設定画面で C 長押し（約1秒） | 設定 AP を閉じてメイン画面に戻る |

画面は初版から右（時計回り）に90度回転した240×320の縦向きです。上部は北が上のレーダーです。赤い三角が機体の進行方向、方向が不明なら点で表示します。
コールサイン、取得できる高度（ft）を表示し、位置を持たない機体・古い位置・地上機は除外します。
機種名はローカル JSON に `t` がある場合だけ表示します。通常の mutability には機種名がないため空欄です。

リング上の距離表記は元実装と同じく **第3リング** の距離です。下部の **R …km** が最外周の半径です。

| 第3リング | 最外周半径 |
|---|---|
| 5 km | 約 6.7 km |
| 10 km | 約 13.3 km |
| 15 km | 20 km |
| 25 km | 約 33.3 km |
| 50 km | 約 66.7 km |
| 100 km | 約 133.3 km |

下部の **AC** は取り込んだ範囲内の機体数です。最大64機で、超える場合は近い機体を優先します。
外周付近の点は方向を示すもので、その点自体は正確な距離を示しません。
元実装の滑走路オーバーレイは残していますが、これは地図全体を描く機能ではありません。

## 更新・切断時の動作

- 正常時は取得完了から約3秒後に次の取得を開始します。
- 位置の経過時間 `seen_pos` と取得後の時間を合算し、15秒を超えた機体を消します。
- HTTPが成功しても `now` が前回と同じなら、位置情報を新しいものとして扱いません。
- 最後の新しいデータから15秒を超えると **STALE** と表示します。
- Wi-Fi切断は **OFFLINE**。保存済み Wi-Fi へ自動再接続を試みます。自宅ルーターより先に起動した場合も再試行します。
- **LIVE / AC 0** は正常取得した結果、範囲内の表示対象が0機だった状態です。

外部の時刻サーバーには依存しません。このため、起動直後にサーバーが返したファイルの絶対的な古さは判定できません。同一 `now` の停止検知は2回目以降の取得で行います。
HTTP処理は時間制限付きの同期処理です。正常なLANでは短時間ですが、サーバー不通時などは数秒間ボタンや表示更新が遅れる場合があります。

## ファームウェアを書き込む

配布 ZIP の `firmware/m5stack-basic-merged.bin` は **Basic / Gray の ESP32 用**です。
ESP32-C3 や CoreS3 用ではありません。既存の本体アプリを置き換えます。

Python と esptool を使う場合（PowerShell、COM番号は実機に合わせる）：

```powershell
python -m pip install esptool==4.5.1
python -m esptool --chip esp32 --port COM5 --baud 460800 write_flash 0x0 firmware/m5stack-basic-merged.bin
```

書き込み後に本体をリセットしてください。通常は自動で書き込みモードへ入ります。接続に失敗する場合は、データ対応USBケーブルとCOMポート、機種のUSBドライバーを確認してください。
**結合済み merged.bin は初回導入用です。設定領域も上書きするため、Wi-Fiと座標を再設定します。**
このファームウェアの設定を残して更新する場合は、下記の `pio run -t upload` を使うか、アプリ本体だけを書き込みます。

```powershell
python -m esptool --chip esp32 --port COM5 --baud 460800 write_flash 0x10000 firmware/firmware.bin
```

アプリ本体だけの更新は、同梱パーティション構成がすでに入っている場合に限ります。

## ソースからビルド

PlatformIO Core または VS Code の PlatformIO 拡張を使用します。

```powershell
python -m pip install platformio
pio run -e basic
pio run -e basic -t upload --upload-port COM5
pio device monitor --port COM5 --baud 115200
```

リポジトリルート（このREADMEのあるフォルダ）で実行してください。
`basic` は4 MBのフラッシュ領域内に収まる構成です。16 MB搭載版でも残りのフラッシュ領域は使用しません。
`core2` 環境も残していますが、この配布の検証対象・書き込み済みバイナリは **basic** です。

## トラブルシューティング

| 表示 / 症状 | 確認すること |
|---|---|
| BAD URL | `http://` で始まる機体JSONの完全なURLか。HTTPSや認証付きURLには未対応 |
| BAD LAT/LON | 空欄、全角数字、緯度経度の取り違え、範囲外の値がないか |
| HTTP 404 | レーダー画面のURLではなく `aircraft.json` 自体を指定しているか |
| HTTP ERROR | サーバー起動、同一LAN、無線APのクライアント分離、ファイアウォール |
| BAD SCHEMA | JSONルートに `aircraft` 配列と数値 `now` があるか |
| JSON ERROR | 壊れたJSON、HTMLのエラーページ、またはJSON処理メモリの上限超過 |
| BODY ERROR | タイムアウト、途中切断、本文64 KiB超過、メモリ確保失敗 |
| ENCODING | HTTP/1.0でもchunkedや圧縮を返すプロキシ。通常の非圧縮JSONを返すよう設定 |
| STALE | dump1090自体が更新中か、静的な古いファイルを返していないか |
| 機体が出ない | 中心座標、Aで距離拡大、位置付き機体が受信できているか |

64 KiBのHTTP本文、48 KiBのフィルター済みJSON文書、64機の表示上限を設けています。
大量の機体を返す環境では上限エラーになることがあります。今回は提供された約5 KiBの実データでパーサーを検証しています。
